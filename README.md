# 🏺 Artesanía Albaicín — Management System

🌐 **English** · [Español](README.es.md)

Full-stack application for a handicraft shop in the Albaicín district of Granada (Spain). It has three parts: a **public website** for tourists, an **admin panel** for the shop staff, and a **REST API** that connects both.

> **Status:** working project, not deployed yet. See the [Roadmap](#roadmap).

## Features

**Public website**
- Product catalogue filtered by category, with product detail pages.
- Contact form that stores messages in the database.
- Animations (AOS), SEO metadata and responsive layout.

**Admin panel**
- Login with role-based access (`admin` and `encargado`).
- Product, category and image management (images stored in Cloudinary).
- Daily sales register with payment method (card/cash) and discounts.
- Dashboard with sales charts and counters (unread messages, sold-out products).
- Contact message inbox.

**API**
- JWT authentication, passwords hashed with bcrypt.
- Input validation with Pydantic (invalid roles, payment methods, negative amounts… are rejected with a 422).
- Automatic SQLite backups (at start-up and every day at midnight, keeping the last 7), using SQLite's own backup API.
- Image uploads limited to JPG, PNG and WEBP up to 5 MB.
- Interactive documentation generated by FastAPI at `/docs`.

## Getting started

### Requirements
- Python 3.14 (the version used in development)
- Node.js 24 (the version used in development) and npm
- A free [Cloudinary](https://cloudinary.com) account for image storage

### 1. Clone the repository
```bash
git clone https://github.com/ZakariaeBouhaba/artesania-albaicin-personal.git
cd artesania-albaicin-personal
```

### 2. Backend
```bash
cd backend
python3 -m venv venv
source venv/bin/activate        # Windows: venv\Scripts\activate
pip install -r requirements.txt
```

Create a `.env` file inside `backend/` (it is ignored by Git):

```env
SECRET_KEY=<generate one, see below>
ALGORITHM=HS256
ACCESS_TOKEN_EXPIRE_MINUTES=480
CLOUDINARY_CLOUD_NAME=<your cloud name>
CLOUDINARY_API_KEY=<your api key>
CLOUDINARY_API_SECRET=<your api secret>
```

Generate a strong secret key with:
```bash
python3 -c "import secrets; print(secrets.token_hex(32))"
```

Create the first administrator (the script asks for email and password, nothing is stored in the code):
```bash
python3 crear_admin.py
```

Start the API:
```bash
python3 main.py
```
The database file (`artesania.db`) is created automatically on first run.

### 3. Public website
```bash
cd frontend
npm install
npm run dev
```

### 4. Admin panel
```bash
cd panel
npm install
npm run dev
```

| Register, list and view sales | ❌ | ✅ | ✅ |
| View statistics | ❌ | ✅ | ✅ |

| Create / edit / delete products, categories and images | ❌ | ❌ | ✅ |
| Delete sales | ❌ | ❌ | ✅ |

## Database

SQLite with SQLAlchemy. Tables: `usuarios`, `categorias`, `productos`, `imagenes_productos`, `mensajes`, `ventas`.

- Product status: `disponible`, `agotado`, `bajo_pedido`.
- Payment method: `TPV` (card) or `Efectivo` (cash).
- The sale total is calculated by the server (`precio_original − descuento`), never trusted from the client.

> **Upgrading an older database:** the `imagenes_productos` table now has a `public_id` column. If you already have a database, add it with
> `sqlite3 artesania.db "ALTER TABLE imagenes_productos ADD COLUMN public_id VARCHAR;"`

## Technical decisions

- **Three separate apps** instead of one: the public site and the admin panel have different users, different bundles and can be deployed independently.
- **Dependency-based authorisation** (`Depends(get_admin_user)`) so every route declares its required role in its signature.
- **Images in Cloudinary** instead of the local disk, so they survive server restarts. The real `public_id` is stored in the database so images can be deleted reliably, including when a product is removed.
- **Validation at the schema level** (`Literal`, `EmailStr`, `Field(ge=0)`) rather than manual `if` checks: invalid data never reaches the business logic and the rules appear automatically in `/docs`.
- **Safe backups** with SQLite's backup API instead of copying the file, which can produce a corrupt copy while the database is being written.
